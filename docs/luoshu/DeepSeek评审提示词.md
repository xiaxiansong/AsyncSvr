```text
# 任务
你是华为终端鸿蒙系统能力 swing_service 的测试专家，也是本任务的主 agent。请评审并完善“洛书（屏幕感知）多机型适配”的真机手工测试用例，最终输出一个 Excel 文件。文件中要包含所有机型的公共测试用例，以及三折叠、双折叠、阔折叠、小折叠各自的专项测试用例。你可以开子 agent 并行工作。

# 输入
- 待评审用例目录：{docs/luoshu 目录路径}
  - 洛书多机型适配测试用例.md：用例的可读版本
  - cases.py：用例数据源（COMMON/TRI/DUAL/WIDE/FLIP 列表、SUPPORT 支持性、SCENARIOS 支持场景清单、NON_MANUAL 非手工项）
  - gen.py：运行 `python3 gen.py <输出目录>` 后，由 cases.py 生成 Excel 和 md
- swing_service 源码：{源码目录路径}
- 历史测试用例：{历史用例路径}

# 背景
- 洛书是鸿蒙的 AI 伴随功能。swing_service 不实现算法，是系统级桥接与治理层，职责如下：
  1. 接入鉴权：SUBSCRIBE_SWING_ABILITY 权限、事件名→eventId 映射、domainId 校验
  2. 事件生命周期：订阅/退订、引用计数、睡眠/S4 不注册、相机互斥白名单、901/903 不支持预加载
  3. 参数下发：SwingParameter.json、SetParam 命令码 1/79/73、EnableEvent
  4. 数据通道：SendFileByFd、DataType→64/65/66/81/67/77、fd 关闭
  5. 设备状态注入：stateId=0 折叠相机切换、1 亮灭屏、2 旋转、3 折叠；903 专属 78 物理方向、80 折叠状态
  6. 结果分发：OnIgsEventDone→publishSwingEvent；901 结果不打日志
  7. 可靠性：OnServiceDied 重连、SensorHub 参数重放、HiSysEvent 打点
- 901 = ACTIVE_SCREEN_AWARENESS（屏幕感知），903 = GAME_OCR_UNDERSTAND（游戏理解）。
- 本次重点是多机型适配：三折叠、双折叠（内折）、阔折叠、小折叠（上下翻折）。
- 用例由测试人员拿真机手工执行，同时抓 hilog 核对。步骤里不能出现调用接口、root、kill 系统服务这类操作；这类测试点放入 NON_MANUAL。

# 工作流程

## 第 1 步：源码事实提取（开 1 个子 agent，必须先完成）
阅读 swing_service 源码，输出《源码事实.md》。每一条都要注明“文件名:行号”或函数名。内容包括：
1. 睡眠/S4 的判断条件和处理方式
2. 相机互斥白名单内容，以及非白名单事件的处理
3. FoldStatus→注入值的完整映射表；是否覆盖三折叠扩展状态（*_WITH_SECOND_*）；遇到未知状态时怎么处理
4. HALF_FOLD 的 DisplayMode 判断逻辑
5. 外屏（MAIN/SUB display mode）是否有特殊处理
6. 旋转：phyrotation.offset、rotation_correction、PC 旋转偏置的读取和计算方式；平放（方向不确定）时怎么处理
7. 折叠相机切换（stateId=0）的触发条件和 cameraId 取值
8. pc/pad/tv judge 的判断条件
9. 投屏、外接屏、分屏、多用户、省电模式下是否有特殊处理
10. 每项职责在源码中实际打印的日志关键字或格式（用于替换用例里的“建议关键字”）
11. 如果源码或配置中能找到各机型、各形态、各方向的期望注入值，一并列出
最后，逐条确认 cases.py 中 SCENARIOS 的每个场景：支持 / 不支持 / 部分支持 / 无法确认（写明需要问业务方、算法方还是 DMS）。

## 第 2 步：分页评审（开 5 个子 agent 并行：公共、三折叠、双折叠、阔折叠、小折叠，各负责一页）
每个子 agent 都拿到《源码事实.md》、历史用例和自己负责的那页用例，按以下要求处理：
1. 逐条评审，结论为：保留 / 修改 / 删除 / 合并到某条 / 转非手工。
2. 场景支持性以《源码事实.md》为准，填：支持 / 不支持 / 部分支持 / 无法确认。
   - 不支持是正常现象。这类用例的预期结果必须写成“正确拒绝”：不工作或给出提示、不闪退、日志无 error 级异常、退出该场景后无需重新开启即可恢复。不能写成“结果正常”。
3. 日志核对点里的“建议关键字”，替换为源码中实际的日志关键字。
4. 补充用户真实使用场景。重点是用户怎么用这台折叠机：开合、悬停、外屏、横竖持、应用接续、分屏、平放、晃动等。每个机型至少覆盖以下维度：
   初始状态注入、折叠状态映射、半折判断、各屏幕四个方向、相机切换、切屏不误报灭屏、使用中开合不中断、快速开合。
5. 写法参考历史用例的粒度和措辞。
6. 交付物：修改后的用例条目（必须符合 cases.py 的数据结构，见下方“格式约束”），以及一份评审记录（编号 | 结论 | 支持性 | 源码依据 | 修改说明）。

## 第 3 步：合并与生成（主 agent）
1. 把 5 个子 agent 的结果合并进 cases.py：
   - 去掉重复：公共用例已覆盖的，不再在机型页重复；各机型页都出现的同类用例，上移到公共用例。
   - 原有编号保持不变；新增用例按页往后编号；删除的用例直接删掉，不要留空号说明。
   - 更新 SUPPORT（每条用例的支持性，默认“支持”）、SCENARIOS（初判列改为确认结论，并附源码依据）、NON_MANUAL。
   - 如果新增用例用了新的覆盖维度标签，同时加到 gen.py 的 DIMS 列表中。
2. 运行：python3 gen.py <输出目录>
3. 如果第 1 步找到了期望注入值，用 openpyxl 填入生成的 Excel《预期值对照表》的黄色单元格。
4. 将最终文件命名为“洛书多机型适配测试用例_终版.xlsx”。

## 第 4 步：自检（主 agent，不通过就返回修改）
- 每条用例的测试步骤和预期结果条数一一对应，编号连续
- 没有残留“待确认”；“无法确认”必须写明原因和该问谁
- 没有编造源码中不存在的逻辑或日志关键字
- 所有步骤都能在真机上手工完成，预期结果可以观察、可以判定
- 四个机型都覆盖了第 2 步第 4 条列出的全部维度（查看 Excel《覆盖矩阵》页）
- 预期不支持的用例，预期结果都是“正确拒绝”的写法
- gen.py 运行成功，Excel 能正常打开

# 格式约束（cases.py 的数据结构，不能改）
每条用例是一个 8 元组：
("编号", "级别 L0/L1/L2", "用例名称", [预置条件...], [测试步骤...], [预期结果...], [日志核对点...], [覆盖维度标签...])
- 测试步骤和预期结果的列表长度必须相等，第 i 条预期对应第 i 条步骤
- 用例名称参考格式：“首次开启光环境健康检测，按照引导操作”，即说明用户在做什么
- 用【屏幕感知】【游戏理解】作为入口简称
- 编号前缀：LS_COMM_ / LS_TRI_ / LS_DUAL_ / LS_WIDE_ / LS_FLIP_

4. 更新后的 cases.py
如果运行环境无法执行 Python：按 洛书多机型适配测试用例.md 的现有格式，输出“洛书多机型适配测试用例_终版.md”作为主交付物，并在回复中说明原因。
```
